== NAME

friedentools - A clean-room, unencumbered, universally compatible asset compiler and builder suite for classic 2.5D game archives

== SYNOPSIS

*friedentools* `-u` | `--unpack` _<input.wad>_ _<output_directory>_ [`--mus2mid`]

*friedentools* `-p` | `--pack` _<input_directory>_ _<output.wad>_ _<IWAD|PWAD>_

*friedentools* `-t` | `--texture` _<texture.txt>_ _<output_pnames.lmp>_ _<output_texture1.lmp>_

*friedentools* `-f` | `--flat` _<input_image.png>_ _<output_flat.lmp>_

*friedentools* `-s` | `--sound` _<input_audio.wav>_ _<output_sound.lmp>_

*friedentools* `-g` | `--graphic` _<input.png>_ _<playpal.lmp>_ _<output.lmp>_ _<origin_x>_ _<origin_y>_

== DESCRIPTION

*friedentools* is a modular, dependency-free, cross-platform multimedia compiler toolset built completely from scratch in pure C.

It was engineered under the strict parameters of the permissive 3-Clause BSD License to provide a legally unencumbered toolkit for building standalone game assets and managing WAD archive databases without requiring proprietary toolchains or legacy software dependencies.

Every binary compilation pass enforced by the tool chain adheres to universal architectural alignments (padding all output data structures to strict 4-byte boundaries and normalizing file identifiers to uppercase strings), guaranteeing 100% stable compatibility with historical executables and modern source port engines.

== OPTIONS

`-u`, `--unpack` _<wad>_ _<dir>_ [`--mus2mid`]::
  Decomposes a primary data package file into structured subdirectories. Employs a dynamic namespace splitter loop that strips section fence markers, isolating mapped elements to safeguard directories against file namespace duplication collisions and text truncation overwrites.
  +
  If the optional `--mus2mid` parameter switch is present, the extraction engine scans every incoming binary lump for the legacy compressed music signature format (`"MUS\x1A"`). Matching entries are automatically transcoded on-the-fly and written out exclusively as standard Type 0 MIDI payloads with a clean `.mid` extension suffix rather than raw unmodified file blocks.

`-p`, `--pack` _<dir>_ _<wad>_ _<type>_::
  Crawls a target folder architecture line-by-line using custom text manifests, encoding raw structural layout records sequentially into a finalized little-endian binary archive. Validates input types to append proper "IWAD" or "PWAD" signature tags.

`-t`, `--texture` _<txt>_ _<pn>_ _<tx1>_::
  Parses human-readable multi-patch composition layout blueprints and serializes them into mathematically synchronized binary *PNAMES* and *TEXTURE1* registry index lumps. Includes automatic 4-byte boundary offset padding checks to block hardware alignment memory faults.

`-f`, `--flat` _<image>_ _<output.lmp>_::
  Uses integrated single-header decoding arrays to validate and strip a source file down into a raw 4,096-byte array representing a 64x64 uncompressed floor or ceiling tile.

`-s`, `--sound` _<wav>_ _<output.lmp>_::
  Decodes a digital audio track, performs a high-precision monaural mixdown pass, and employs fractional linear interpolation to down-sample the waveform to the standard 11,025 Hz frequency layer. It serializes data with the explicit structural padding rings and offset counters required by hyper-sensitive vanilla validation loops.

`-g`, `--graphic` _<png>_ _<pal>_ _<out>_ _<x>_ _<y>_::
  Translates modern 32-bit transparent graphics into column-oriented binary bitstreams. Implements a 3D Euclidean distance vector matching engine that automatically quantizes colors directly down to the 256-color index table coordinates of a target master palette while executing alpha-channel bounding box edge trimming.

== EXIT STATUS
